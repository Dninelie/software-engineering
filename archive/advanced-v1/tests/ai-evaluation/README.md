# AI 评测样本合同

第一版不提供假装已标注的真实评测集。团队在 P1/P3 创建 samples.jsonl，每行一个样本：

```json
{"sampleId":"s001","split":"test","sourcePostId":"1001","candidatePostIds":["2001","2002"],"relevantPostIds":["2002"],"tags":["no-source-image","similar-wording"]}
```

以上 ID 仅演示字段，不是实际数据库记录。帖子数据、图片授权和标注依据应另存 fixtures 并通过版本关联。split=train/tune/test 由团队约定，调权只能用 tune，不能反复看 test 调整。

## 指标怎样计算

对每个有正确候选的样本：

```text
单样本 Recall@5 = 前五条中正确候选的数量 / 该样本全部正确候选的数量
总体 Recall@5 = 所有有正例样本的单样本召回率的平均值
```

例如有 2 条正确候选，前五条找回 1 条，则本样本的 Recall@5 为 50%。候选召回阶段漏掉的正确记录仍计入分母。

无正确候选样本使用 `relevantPostIds=[]`，不加入 Recall 分母。单独统计：在这些样本中，仍给出至少一条推荐的样本比例，作为无正例误推荐率。

规则与混合模式使用相同样本、候选和推荐阈值口径，记录未命中的原因。

results/ 后续记录：样本版本、模型/算法版本、模式、排序、候选覆盖、理由、耗时、调用量与错误。不保存真实隐私和密钥，不声称模板数据代表实际效果。
