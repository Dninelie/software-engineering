# 实施计划

先统一接口与状态，再验证关键能力，随后完成规则业务和 AI 增强。

人员对应固定为：A 小程序、B 业务后端、C AI 与任务、D 平台与管理后台。姓名、工期、账号尚待填写。

## 1. 阶段总览

| 阶段 | 目标 | 通过条件 |
|---|---|---|
| P0 约定 | 需求、目录、接口、数据 | 四人使用相同合同 |
| P1 验证 | 真机、服务和任务基础 | 登录上传、真实模型、任务恢复 |
| P2 闭环 | 规则业务完整运行 | 无 AI 也能归还 |
| P3 增强 | AI 草稿和语义推荐 | 真实效果、失败降级 |
| P4 交付 | 验收、部署和答辩 | 关键用例通过，证据齐全 |

## 2. P0：统一约定

共同确认 [需求](01-requirements.md)、[接口](04-api-contracts.md)、[数据](03-database.md)、[文件归属](11-file-ownership.md)。

B 确定认领状态；C 确定任务和 AI 状态；D 确定登录、上传和公共返回；A 反馈页面需要的字段。

不要让 A 从多个后端草稿中自行猜测最终合同。

## 3. P1：验证可行性

| 人员 | 工作 |
|---|---|
| A | 初始化完整小程序，公共请求、导航、模拟页面 |
| B | 初始化业务模块，公开 PostQueryService 和通知合同，准备业务示例 |
| C | 真实图文/向量调用、job 入队/执行/恢复，准备 AI 示例 |
| D | 后端构建、迁移基础、微信登录、文件、服务器和管理端初始化 |

通过条件：

- A 与 D：真机登录、上传、公开与私密图片。
- C 与 D：实际部署网络调用两类模型。
- B 与 C：发布事务可持久入队，调度能读取已提交任务。
- C：执行中重启可恢复，旧租约不能提交。

P1 未通过前不做复杂美化和扩展功能。

## 4. P2：完成规则业务

| 人员 | 工作 |
|---|---|
| A | 所有核心页面与 B/D 接口联调 |
| B | 发布、搜索、线索、申请、交接、归还和站内消息 |
| C | 规则召回、排序、版本、任务，向 A 提供推荐接口 |
| D | 登录/文件稳定化，举报、字典和基础后台 |

通过条件：无需 AI，真机可从发布走到归还；并发认领和对象权限正确。

## 5. P3：AI 增强

| 人员 | 工作 |
|---|---|
| A | 接 C 的草稿、任务和推荐；处理等待、失败、回来恢复 |
| B | 正式特征、版本、私密信息边界、匹配通知联调 |
| C | 特征提取、向量、混合排序、成本控制、独立评测 |
| D | 服务器配置、模型密钥注入、文件读取和运行监控 |

通过条件：无图失主可匹配；AI 故障退回基础能力；任务不覆盖新版本；真实效果有记录。

## 6. P4：验收交付

| 人员 | 主导验收 |
|---|---|
| A | 小程序整体体验、真机演示与页面恢复 |
| B | 完整归还、并发、业务权限、通知 |
| C | AI 效果、时延、费用、任务故障恢复 |
| D | 管理后台、部署、密钥与备份恢复 |

A 组织完整学生端演示，但各人提供自己模块的证据。订阅消息按账号能力决定是否增加，不影响必做验收。

## 7. 工作量控制

A 优先复用表单、列表、详情和状态组件。B 先规则业务闭环，不等待真实模型。

C 完整维护 job，不再等待 D 编写任务框架。D 优先登录和文件，再完成后台页面。

不通过把小程序再拆给 B/C/D 来平衡工期；优先减小第一版功能和管理端美化范围。

## 8. 风险与应对

| 风险 | 提前验证 | 应对 |
|---|---|---|
| 模型不可达或超额 | P1，C 与 D | 更换适配器，保留规则，不以 mock 冒充验收 |
| A 等接口 | P0 示例，P1 mock | B/C/D 先交合同和示例 |
| 服务循环依赖 | P1 应用层设计 | 查询/命令分开，JobService 不直接依赖 handler |
| 私密图无法展示 | P1 真机 | 访问许可，不把 token 放图片地址 |
| 并发或重启不一致 | P1/P2 集成测试 | 事务、版本、租约、幂等 |
| 工期不足 | 每阶段检查 | 先保完整闭环，扩展与美化后置 |

## 9. 待确认项

| 项目 | 负责人 | 确认阶段 |
|---|---|---|
| 姓名与截止时间 | 四人 | P0 |
| AppID 和开发权限 | D，A 验证 | P1 |
| 课程报告模板 | 四人 | P0 |
| 服务器、HTTPS、精确依赖 | D | P1 |
| 模型、费用、配额 | C，D 协助配置 | P1 |
| 校园分类地点 | D 录入，四人核实 | P1–P2 |
| 订阅消息模板 | B 与 D | P4 前决定 |

## 10. 完成定义

代码可运行、迁移可重建、合同一致、关键用例通过、真实微信和 AI 有证据、演示数据可恢复。

文档已完成不代表系统已实现。
