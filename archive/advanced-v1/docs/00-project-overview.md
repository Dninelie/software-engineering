# 项目概览

这份文档适合第一次了解项目的队员。读完后，应能说明项目的用户、主要流程和 AI 的作用。

## 1. 我们要解决什么问题

校园失物信息分散在群聊、朋友圈或线下招领处。失主需要反复翻找，拾取者也很难找到物主。

平台把寻物和招领信息集中起来，并根据物品特征推荐可能相关的信息，帮助双方完成核验和归还。

## 2. 三种角色

| 角色 | 可以做什么 |
|---|---|
| 访客 | 浏览正常公开的信息、搜索和筛选 |
| 登录用户 | 发布、提供线索、申请认领、处理自己的信息 |
| 管理员 | 处理举报、下架违规信息、维护分类和校园地点 |

“失主”“拾取者”“线索提供者”是业务中的身份，同一个登录用户可以在不同事件中担任不同身份。

微信登录用于建立平台账号，第一版不验证用户是否在校。

## 3. 两种信息，不同入口

| 信息 | 谁发布 | 其他人主要做什么 |
|---|---|---|
| 寻物启事 | 丢东西的人 | 提供目击线索，查看相关招领 |
| 招领信息 | 捡东西的人 | 申请认领并提交证明 |

**线索与认领不是同一件事。** 线索是帮助寻找；认领是针对已被拾取的物品申请归还。

## 4. 一次完整使用过程

以丢失保温杯为例：

1. 失主发布寻物：“黑色保温杯，银色杯盖，昨天下午在二食堂附近丢失。”
2. 拾取者发布招领，可以上传照片。
3. AI 帮拾取者整理照片中的可见特征，由拾取者确认。
4. 系统综合描述、时间、地点，向双方推荐相关信息。
5. 失主提交未公开的特殊标记等核验材料。
6. 拾取者接受申请，双方获取交接联系方式。
7. 线下交接后，拾取者确认归还，系统更新相关状态。

没有照片的失主可以直接用文字参与匹配。

## 5. AI 具体做什么

| 能力 | 用户得到什么 | 人工仍需做什么 |
|---|---|---|
| 文字提取 | 从一句话生成表单草稿 | 确认时间、地点和特征 |
| 图片提取 | 从照片生成外观建议 | 修改识别错误、补充遗漏 |
| 语义匹配 | 关联“蓝牙耳塞”和“无线耳机”等相近说法 | 判断是否值得联系、核验归属 |

第一版图片路线是“图片提取特征，再参与文字匹配”。不训练模型，不自动批准认领。

## 6. 系统由什么组成

| 部分 | 技术方向 | 用途 |
|---|---|---|
| 小程序 | 微信原生开发 | 学生发布、查找、认领 |
| 管理后台 | Vue | 平台管理 |
| 业务后端 | Spring Boot | 权限、业务、AI 调用 |
| 数据与文件 | MySQL、文件存储 | 保存信息、任务和附件 |

第一版做一个后端应用，内部按模块分工，适合四人协作。

## 7. 四个人怎样协作

| 成员 | 维护范围 |
|---|---|
| A | 整个微信小程序 |
| B | 信息、认领、归还和消息的业务后端 |
| C | AI、匹配与持久任务 |
| D | 登录、文件、管理后台与部署 |

前后端以接口协作，小程序页面不再分给多个人。代码归属见 [文件清单](11-file-ownership.md)。
