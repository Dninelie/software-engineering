# 部署与配置

本文件面向 D 和参与联调的队员，说明环境、配置和演示准备。

> 当前只有骨架与模板，没有构建文件和可执行部署脚本，尚不能直接启动。

## 1. 需要准备的环境

| 环境 | 用途 | 要点 |
|---|---|---|
| 本地开发 | 编码、模拟、模块测试 | 虚构数据、独立数据库 |
| 联调体验 | 真机与真实 AI | HTTPS、实际 AppID、受控额度 |
| 课设演示 | 答辩和验收 | 固定代码、数据与模型配置 |

D 锁定兼容 Java 21 的后端依赖，A、D 锁定前端工具版本。模拟登录仅用于开发，不能成为公开环境的鉴权入口。

## 2. 第一版怎样部署

```text
小程序 ───────┐
              ├─ HTTPS 反向代理 ─ 后端单实例 ─ MySQL
管理端静态页 ─┘                      │
                                    ├─ 持久化文件目录
                                    └─ 外部模型服务
```

后台任务与普通接口先在同一个后端进程内运行，线程池隔离。C 维护任务执行逻辑与故障恢复；D 负责进程、配置、持久化和部署，二者共同验证运行环境。

| 资源 | 保存要求 |
|---|---|
| MySQL | 持久化数据目录 |
| 图片 | 持久化文件目录，不用系统临时目录 |
| 日志 | 受控目录与必要保留期 |
| 机密配置 | 服务器注入，不放前端和仓库 |

管理端和 API 建议同源，开发跨域只放行需要的来源。数据库不作为公网业务接口。

若使用容器，显式挂载数据库和文件卷。第一版不要求 Kubernetes、缓存或独立对象存储。

## 3. 配置怎样填写

模板：[deploy/.env.example](../deploy/.env.example)。

模板只是变量名称约定。工程初始化时需明确怎样加载并绑定 Spring 配置，不能假定 .env 自动生效。

### 服务、数据库与文件

| 变量 | 用途 |
|---|---|
| APP_ENV | 当前环境 |
| APP_PUBLIC_BASE_URL | 公共访问地址 |
| SERVER_PORT | 后端端口 |
| CAMPUS_TIME_ZONE | 校园日期换算时区，初版 Asia/Shanghai |
| DB_URL | 数据库地址 |
| DB_USERNAME、DB_PASSWORD | 数据库凭据 |
| STORAGE_ROOT | 文件持久化目录 |
| FILE_SIGNING_SECRET | 临时文件许可签名密钥 |

### 微信

| 变量 | 用途 |
|---|---|
| WECHAT_APP_ID | 小程序身份 |
| WECHAT_APP_SECRET | 微信服务端密钥 |

### AI

| 变量 | 用途 |
|---|---|
| AI_MODE | disabled、mock 或 real |
| AI_VISION_BASE_URL、AI_VISION_API_KEY、AI_VISION_MODEL | 图文服务配置 |
| AI_EMBEDDING_BASE_URL、AI_EMBEDDING_API_KEY、AI_EMBEDDING_MODEL | 向量服务配置 |
| AI_WORKER_CONCURRENCY | 模型线程并发 |
| AI_MAX_ATTEMPTS | 尝试次数上限 |
| AI_DAILY_LIMIT | 每日调用额度；0 禁止付费调用 |

disabled 保留规则业务；mock 用于联调；真实 AI 验收使用 real。

平台登录采用随机 token，数据库存哈希和期限，无需 JWT 签名密钥。管理员初始密码安全创建，不在文档提供通用默认密码。

## 4. 首次联调按什么顺序做

1. **账号权限：**建立小程序，邀请四人协作，记录 AppID。
2. **基础工程：**初始化后端、数据库和迁移。
3. **登录：**真机 code 交换，取得平台 token。
4. **文件：**上传、公开图和私密许可展示。
5. **模型：**从实际服务器调用两类服务，核对时延和额度。
6. **真机网络：**配置 HTTPS 和所需域名，验证体验环境。
7. **任务恢复：**C 主导执行中重启测试，D 协助操作进程，验证租约、重试和幂等结果。

账号模板与控制台能力以实际微信账号为准，订阅通知不作为基础流程前提。

## 5. 日志与备份

### 记录什么

requestId、jobId、业务 ID、安全错误码、时延。

### 不应默认记录什么

登录 code、token、密码、模型 key、证明、完整用户描述和私密图片 URL。代理日志也需检查查询参数。

### 监测什么

数据库连接、排队数量、长期执行任务、模型成功率、超时、限流和日额度。

### 怎样备份

同时备份数据库与关联文件，并演练恢复。只有 SQL 备份无法恢复图片。临时文件清理排除有效业务和任务引用。

## 6. 演示前检查

- [ ] 代码、依赖、数据和模型版本固定。
- [ ] 数据库迁移和关键回归通过。
- [ ] 真机登录、上传、预览、查询正常。
- [ ] 密钥只在后端，模拟登录已关闭。
- [ ] 真实 AI 额度足够，规则降级有效。
- [ ] 演示样本虚构或获得授权。
- [ ] 站内消息不依赖微信外部推送。
- [ ] 演示数据和文件有备份。
