# 设计审查与开工条件

审查日期：2026-10-16。范围：目录、需求、接口、数据、依赖、事务和异步流程。

## 1. 结论与边界

按修订后的设计，可进入工程初始化与可行性验证。**一个后端、一个数据源、一个事务管理器**是本版方案的前提。

目前无可运行业务代码，本轮是设计与静态合同审查，不代表真机、数据库并发、模型效果或性能已经通过。

## 2. 发现与修订

| 编号 | 原风险 | 修订 |
|---|---|---|
| R-01 | 同一 LOST 在不同 FOUND 同时被接受 | 锁两端并当前读检查唯一交接 |
| R-02 | 拾取者无法取消 ACCEPTED | 接受后双方可取消，记录人和原因 |
| R-03 | 内容版本去重阻止恢复后刷新 | 增加目标 rowVersion、算法版本和 runSeq |
| R-04 | 匹配任务有编号没有查询入口 | 增加查询并验证用户、目标与类型 |
| R-05 | 校验到写结果之间仍可被编辑 | 同一短事务锁双方 post 和 job 后校验写入 |
| R-06 | 业务、文件、管理服务可能循环注入 | 查询与装配分离，固定只读策略 |
| R-07 | 队列忙或模型额度使发布回滚 | 业务刷新落库不受模型繁忙拒绝 |
| R-08 | 下架 LOST 未释放另一条 FOUND | 工作流处理两端、申请与受影响版本 |
| R-09 | 声称管理员可看证明却无接口 | 第一版默认不开放原始证明 |
| R-10 | 详情缺编辑所需 ID | 补充分类、地点、附件 ID 与保存结果 |
| R-11 | 精确时间未进入日期筛选 | 服务端派生校园日期 |
| R-12 | 可能为 200 个候选逐个调模型 | 只生成源向量，批量读候选，缺失先规则 |
| R-13 | 状态动作重试产生重复效果 | 动作也带幂等键，先返回同请求结果 |
| R-14 | 签名和缓存绕过下架规则 | 每次读复核关联权限，短期许可、禁止缓存 |
| R-15 | 只有人工表格无法重复检查 | 增加 OpenAPI 合同与结构验证脚本 |
| R-16 | 后台文件读取依赖 HTTP 线程身份 | 显式 ActorContext/TaskActor，不复用请求线程身份 |
| R-17 | 管理端详情没有独立合法入口 | 增加管理员详情，调用业务查询，默认不读证明 |
| R-18 | 物品改描述后仍可接受旧证明 | 申请绑定内容版本，过时重申，交接期间冻结关联信息编辑 |

## 3. 不互相干扰的边界

| 区域 | 主维护 | 对外协作 |
|---|---|---|
| 小程序 | A | 使用 B/C/D 的 API |
| business | B | 调 C 入队、D 基础能力；提供只读查询、通知、工作流 |
| intelligence | C | 调 B 查询/通知、D 文件；不改业务表 |
| platform/common/admin | D | 调 B 管理工作流；不直接改申请表 |

具体合同见 [对接约定](12-integration-contracts.md)。不使用“依赖对方全部 Service”的做法，拆分写用例、只读查询与响应装配。

字段以 [OpenAPI](contracts/openapi.json) 为机器可读合同，[接口说明](04-api-contracts.md) 为中文说明。变更时同时维护。

## 4. 可重复检查

```text
node scripts/verify-design.mjs
```

检查文档链接、JSON、路由、负责人、参数、Schema 引用、公开敏感字段和目录。

该脚本是项目自己的结构检查，不替代完整 OpenAPI 标准验证器，也不能证明真实事务行为。

## 5. 工程阶段的必须关卡

| 关卡 | 主责 | 通过要求 |
|---|---|---|
| G1 基础运行 | D | 工程启动、迁移、事务代理、无循环 Bean |
| G2 微信真机 | A、D | 登录、上传、私密图、前后台恢复 |
| G3 业务并发 | B | 抢同一 FOUND、同一 LOST 抢两件 FOUND、取消与完成竞争 |
| G4 任务恢复 | C | 发布入队原子、旧版本与旧租约不能提交 |
| G5 真实模型 | C、D | 网络、配额、格式、中文、时延和向量 |
| G6 全流程 | 四人 | 归还、越权、下架两端同步、规则降级 |

精确依赖、模型服务、服务器和微信账号能力在 P1 锁定。拆服务或拆数据源后，本地事务方案必须重新设计。
