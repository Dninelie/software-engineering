# 术语说明

遇到名词时按需查阅，不需要在开始开发前全部记住。

## 1. 业务名词

| 名词 | 含义 | 例子 |
|---|---|---|
| 寻物 LOST | 失主发布的信息 | “我的保温杯丢了” |
| 招领 FOUND | 拾取者发布的信息 | “我捡到一个保温杯” |
| 线索 | 帮助寻找的目击信息 | “下午在图书馆见过” |
| 核验材料 | 用于判断归属的私密内容 | 杯底标记、购买证明 |
| 正式特征 | 用户确认并提交的物品描述 | 黑色、银色杯盖 |
| AI 草稿 | 模型建议，尚未正式提交 | 待确认的颜色和类别 |

## 2. 架构与接口

| 名词 | 通俗解释 |
|---|---|
| 模块化单体 | 一个后端应用，内部按业务分模块 |
| API | 前后端约定的请求入口 |
| DTO | 接口专用的数据结构，避免直接暴露整张表 |
| Controller | 接收 HTTP 请求并调用用例的代码 |
| 应用层 | 组织“发布、接受申请”等完整操作 |
| 领域层 | 保存业务规则，例如哪些状态允许认领 |
| Mapper | 读写数据库的代码 |
| Gateway / 适配器 | 包装模型、微信等外部服务，方便替换 |
| token | 平台登录凭证，不是微信 openid |
| openid | 微信为当前小程序识别用户的标识 |
| session_key | 微信会话密钥，只留在服务端 |
| 访问许可 | 校验权限后发放的临时文件读取凭证 |

## 3. 一致性与后台任务

| 名词 | 含义 | 本项目中的作用 |
|---|---|---|
| 事务 | 一组数据库修改一起成功或失败 | 归还时同时更新申请和信息 |
| 幂等 | 同一操作重复请求，仍只产生一次效果 | 防止双击创建两条信息 |
| 乐观锁 rowVersion | 用版本检查数据是否被别人改过 | 防止编辑覆盖刚发生的认领 |
| 内容版本 contentVersion | 标识物品描述是哪一版 | 阻止旧 AI 结果覆盖新描述 |
| 异步任务 | 先接受请求，再在后台执行 | 不让发布页一直等模型 |
| 持久化 | 将状态保存到数据库等长期存储 | 后端重启后任务还在 |
| 租约 lease | 某个执行者在一段时间内拥有任务 | 执行者异常后允许别人接手 |
| handler | 负责某类任务的处理代码 | B 编写提取和匹配处理器 |
| 降级 | 增强能力故障时使用基础能力 | 语义服务失败时规则推荐 |
| mock | 模拟实现 | 页面联调时返回固定示例 |

## 4. 匹配与评测

| 名词 | 含义 |
|---|---|
| 候选召回 | 先从所有信息里找出可能相关的一小批 |
| 规则匹配 | 比较类别、时间、地点和颜色等明确条件 |
| 语义匹配 | 比较描述含义是否接近 |
| 文本向量 embedding | 用一组数字表示文本特征，便于比较 |
| 余弦相似度 | 比较两个向量方向的指标，不是归属概率 |
| 规则与语义混合 | 综合明确条件和语义相似度进行排序 |
| Recall@5 | 前五条找回了多少正确候选；本项目先计算每个有正例样本的召回比例，再取平均 |
| 误推荐率 | 没有正确候选时，系统仍给出推荐的比例 |
| P95 延迟 | 95% 请求耗时不超过的值 |

完整的多正例 Recall 定义与样本规则见 [AI 评测资料](../tests/ai-evaluation/README.md)。
