# 功能与业务规则

本版面向四人课设。只实现发布、查找、AI 辅助、文字线索、认领归还和基础管理，不恢复归档中的复杂机制。

## 1. 角色与范围

| 角色 | 可以做什么 |
|---|---|
| 访客 | 浏览公开信息、搜索、筛选 |
| 登录用户 | 发布、提供线索、申请认领、处理自己的信息 |
| 管理员 | 查询管理信息、下架、处理举报 |

微信身份不等于在校认证。管理员登录与微信登录是两个入口，角色只能由后端确定。

## 2. 第一版功能

| 功能 | 完成要求 |
|---|---|
| 发布与编辑 | LOST 寻物或 FOUND 招领，图片选填，编辑复用发布页 |
| 搜索 | 按类型、关键词、类别、地点分页查询 |
| AI 辅助 | 文字/图片生成建议，用户确认后发布 |
| 规则推荐 | 根据公开特征返回最多 5 条相反类型的信息 |
| 文字线索 | 向 LOST 提交，发布者查看 |
| 认领归还 | 文字核验、接受/拒绝、取消、确认归还 |
| 我的 | 我的发布、发出的申请、收到的申请 |
| 管理 | 举报、信息下架、举报处理 |

小程序七页，管理端三页。详见 [页面设计](05-miniprogram-and-ai.md)。

不自动关联寻物与认领；失主拿回物品后，手动结束自己的寻物。

## 3. 字段与校验

前后端按相同规则校验。文字先去首尾空白，空的可选文字统一保存为空字符串。

| 字段 | 规则 |
|---|---|
| title | 必填，5–50 字 |
| categoryCode | 必选固定字典，含 OTHER |
| eventDate | YYYY-MM-DD，可为 null；不能晚于校园当天 |
| locationCode | 必选固定字典，未知选 UNKNOWN |
| description | 必填，10–1000 字 |
| color | 可空，最多 30 字 |
| brand | 可空，最多 80 字 |
| features | 可空，最多 300 字，建议顿号或逗号分隔 |
| imageIds | 0–3 个不同 ID，本人上传；JPEG/PNG，单张最多 5MiB |
| nickname | 1–30 字 |
| proof、content | 认领证明或线索，1–1000 字 |
| contact | 交接方式，1–100 字 |
| reason、result | 原因或处理说明，必填时 1–500 字 |

只记录大致日期。时段可写描述，不再区分精确时间。

公开图片是物品图；核验秘密放私密文字。第一版不支持证明图片。

### 固定字典

初始类别：CARD、CUP、ELECTRONICS、BOOK、BAG、CLOTHING、OTHER。

初始地点：LIBRARY、CANTEEN、DORM、OTHER、UNKNOWN。

这些是演示编码，D 在接入前与团队确认显示名称。B/C/A 都从 D 的字典能力获取，不各自维护不同版本。

## 4. 信息状态

| 状态 | 含义 | 常见下一步 |
|---|---|---|
| OPEN | 寻找中或待认领 | 编辑、关闭、接受申请 |
| PROCESSING | 招领已接受申请，等待交接 | 取消、归还 |
| RESOLVED | 寻物已找回或招领已归还 | 只读历史 |
| CLOSED | 主动关闭或管理员结束 | 只读历史 |

visible 与业务状态分开：下架设为 false，第一版不提供恢复按钮。

### 信息操作限制

- LOST：本人 OPEN 时可编辑、关闭、标记找回。
- FOUND：本人 OPEN 且无活动申请时可编辑。
- FOUND 有待处理申请仍可关闭，关闭时全部拒绝。
- PROCESSING 不能普通编辑或关闭，先取消或完成交接。
- RESOLVED/CLOSED 不再编辑或重新开启。
- type、ownerId 不能通过编辑修改。
- 编辑或状态/可见性变化时 version 递增。

公开列表和详情只展示 visible=true 且 OPEN/PROCESSING。本人和管理员可读历史物品资料；认领双方可读自己的申请。

## 5. 申请状态与动作

活动申请指 PENDING 或 ACCEPTED。

| 当前状态 | 谁操作 | 动作 | 结果 |
|---|---|---|---|
| PENDING | 拾取者 | 接受 | 申请 ACCEPTED，招领 PROCESSING |
| PENDING | 拾取者 | 拒绝 | 申请 REJECTED |
| PENDING | 申请人 | 撤销 | 申请 CANCELLED |
| ACCEPTED | 任一交接方 | 取消 | 申请 CANCELLED，招领 OPEN |
| ACCEPTED | 拾取者 | 确认实际归还 | 申请 COMPLETED，招领 RESOLVED |

完成归还后，其他 PENDING 改为 REJECTED，原因为“物品已归还”。接受一人时其余 PENDING 暂保留；交接取消后可继续处理。

终态不重新激活。重复动作返回 409，客户端重新查询最新状态，不承诺复杂重试幂等。

### 创建申请

1. 必须登录，只能针对他人的可见 FOUND。
2. 锁对应招领后，先查本人的活动申请；已有则返回原记录。
3. 没有活动申请，再检查 OPEN、postVersion 与参数，创建申请。
4. 有活动申请时禁止编辑该招领，因此不用内容快照和多版本。

## 6. 线索、隐私与管理

- 线索仅向可见 OPEN 的 LOST 提交；不向自己的寻物提供线索。
- 线索列表只给该寻物发布者，第一版不做作者历史页。
- proof 仅认领双方读取，列表不返回正文。
- 自己可见自身联系方式；对方只在 ACCEPTED/COMPLETED 可见。
- 管理员不能凭角色读取原始证明或联系方式。
- 下架时 PENDING 拒绝、ACCEPTED 取消；未解决信息 CLOSED，已归还记录保留 RESOLVED。
- 举报处理与下架是两个动作；处理举报不自动下架。

## 7. 暂不做

消息中心、微信订阅、聊天、导航、学生实名认证、私密图片、持久任务、自动恢复、向量数据库和模型训练。

语义匹配与简单统计是后续加分项，先保证本版流程完整。
